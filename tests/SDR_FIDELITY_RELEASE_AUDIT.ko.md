# SDR 화질 변경 릴리스 검증 (2026-09-19)

## 대상

- v1.2.10 소스(f407c803) 기반 미출시 수정본. 버전 번호와 공개 릴리스는 변경하지 않음.
- SDR Video Processor 자동 보정 비활성화, NV12/YUY2 DirectShow 색 정보 반영,
  실제 1:1 표시에서 Sharp 제외, SDR 출력 Full-range RGB 명시.
- 이번 재검증에서는 테스트를 확대했으며 추가 제품 코드 변경은 하지 않음.

## 결과

- 새로운 `build-sdr-release-check` 디렉터리에서 MSVC 19.39 x64 Release 빌드 성공.
- 전체 CTest 29/29 통과 (133.34초). 생략된 테스트 없음.
- HdrPipelineTests, SdrPipelineTests, VideoColorTests,
  DirectShowVideoFormatTests 각각 5회 반복 통과 (20회 실행).
- 4K SDR GPU 비교: NV12/YUY2 × BT.601/BT.709 × Full/Limited ×
  저지연/VSync/호환성 출력 = 24조합.
- 실제 앱 렌더러의 업로드와 VideoProcessorBlt 출력 픽셀을 CPU 기준값과 비교.
  행 패딩 포함 1픽셀 밝기 무늬 및 균일 색 패치 검증. RGB 허용 오차 3/255.
- VIDEOINFOHEADER2 색 정보 파싱 및 연결된 타입의 색 정보 우선 반영 확인.
- 누락/알 수 없는 색 정보의 기존 기본값 유지, 부분 정보 처리 확인.
- 1:1 Sharp 비활성화, 지원 GPU에서 확대 시 Sharp 활성화,
  재초기화 후 Sharp 상태 제거, Smooth 확대 시 Sharp 비활성화 확인.
- GPU 테스트는 숨긴 창과 합성 입력을 사용함. 모니터의 실제 발광색이나
  드라이버 조합 전체를 측정한 시험이 아니며, 표시 방식별 검사는 Present 이후
  패널 출력이 아니라 해당 스왑체인의 GPU 출력 버퍼 비교임.

## 앞서 수행한 실기기 확인

- 사용자의 GC573에서 수정본으로 NV12 2560×1440 120fps 및
  3840×2160 60fps 출력 확인. 4K 진단의 입력/표시 해상도 일치.
- 짧은 관찰 시점에 프레임 건너뜀과 오디오 underrun 0.
- 4K F11 전환 후 영상 출력 유지. 사용자는 기존 대비 체감 차이가 없다고 응답.
- 원래 2560×1440 자동 프레임 설정으로 복원.
- 직결 동일 장면 A/B, 장시간 시험, Elgato 4K X 및 LG 42C2 실기기 검증은 미실시.

## 배포 크기와 처리 비용

- 기존 배포 EXE 659,456바이트 → 수정 EXE 659,968바이트 (+512바이트).
- 정적 가져오기 DLL 17개로 기존과 동일; 신규 외부 DLL 없음.
- HDR 프레임 저장/scRGB 비교/제조사 톤매핑 실험 빌드 옵션 모두 OFF.
- 변경은 시작/렌더러 초기화 경로에 한정. 프레임 큐, 프레임별 복사나 처리
  패스는 추가하지 않음. 정보가 없는 장치에서는 시작 시 추가 모드 조회가
  발생할 수 있고, 최종 연결 색 정보가 바뀌면 시작 단계에서 렌더러를 다시 생성함.
- 정밀 전후 성능 벤치마크는 하지 않았으므로 성능 차이 0을 보증하지 않음.

## 판단과 한계

확인한 변경 범위에서 릴리스를 막는 결함은 발견되지 않음.
다만 장치가 잘못 보고하는 메타데이터, 다른 GPU의 Video Processor 동작,
HDMI 직접 연결과 캡처의 색차 해상도 차이, TV 입력별 후처리는 이 검사만으로
배제할 수 없음. 해당 사용자의 화질 증상이 해결됐다고 릴리스에 쓰지 말 것.
이번 수정은 BT.601/709 SDR 정보 반영이며 BT.2020/HLG raw SDR 지원 추가가 아님.
