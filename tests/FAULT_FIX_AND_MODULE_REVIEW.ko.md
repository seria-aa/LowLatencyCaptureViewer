# 추가 결함 보완 및 main.cpp 모듈화 검토 — 2026-09-11

이 문서는 `ADDITIONAL_FAULT_AUDIT.ko.md`에서 재현한 조건의 수정 결과다.
과거 감사 기록은 수정 전 동작을 보존하며, 현재 상태는 이 문서를 따른다.
릴리스/업로드/기존 포터블 ZIP 교체는 하지 않았다.

## 보완 내용

- **후보별 형식 검증**: SetFormat을 호출하기 전에 해당 후보의 크기·포맷·행 크기를
  확인한다. 잘못된 후보는 건너뛰고 정상 대체 후보를 시도한다. 선택 실패 때는
  호출자가 보관하던 출력 크기·FPS 값을 변경하지 않는다.
- **기본 시간이 생략된 프레임 범위**: 명시된 Min/MaxFrameInterval 안에 있는
  요청 FPS는 시간값을 채운 별도 후보로 만든다. 기본 시간이 0인 원본은 실행 가능한
  대체 후보로 사용하지 않는다. 범위가 있다는 이유만으로 장치 지원을 확정하지 않고
  실제 SetFormat 성공을 요구한다.
- **조회 성공과 내용 정상 여부 구분**: 알려진 영상 포맷의 빈/잘못된 형식 데이터와
  불가능한 raw payload는 ERROR_INVALID_DATA로 보고한다. 같은 목록의 정상 항목은
  유지하며, 단순히 지원하지 않는 다른 포맷은 오류로 오인하지 않는다.
- **성공+null GetFormat**: 함수 경계에서 ERROR_INVALID_DATA로 변환한다.
- **중첩 출력 전환**: WM_EXITSIZEMOVE가 와도 상위 출력 전환이 남아 있으면
  보류 중인 재생성 요청을 유지한다. 마지막 전환 종료 때 한 번만 갱신한다.

실패 조건의 변경 결과:

| 재현 조건 | 이전 | 수정 후 |
| --- | --- | --- |
| 잘못된 120fps 후보 + 정상 60fps 후보 | 0x8007000D로 중단 | 60fps 선택, 잘못된 후보는 SetFormat 호출 전 제외 |
| 기본 시간 0 + 명시된 60~240fps 범위 | 목록 비어 있음 | 범위 내 9개 공통 FPS 표시, 요청 120fps 실제 협상 |
| 알려진 포맷의 빈 형식 데이터 | S_OK + 빈 목록 | 0x8007000D + 빈 목록 |
| 1080p NV12의 1바이트 payload | S_OK + 사용 가능한 항목처럼 표시 | 0x8007000D, 잘못된 항목 제외 |
| GetFormat 성공+null | S_OK | 0x8007000D |
| 상위 전환 도중 크기 조절 종료 | 조기 1회 + 최종 1회 | 조기 0회 + 최종 1회 |

재발 방지를 위해 `VideoFormatFaults`, `VideoTransitionFaults`,
`VideoLayoutStress`, `VideoMailboxStress`, `VideoTransitionStress`를
기본 CTest에 등록했다. 이전에는 별도 옵션으로만 실행했던 검사들이다.
기본 테스트 수는 15개에서 20개로 늘었다.

## 성능 및 검증 범위

이번 변경은 장치 목록 조회/초기 형식 협상/창 전환 처리에 한정된다.
오디오 처리, PCM 버퍼, 프레임 콜백, 픽셀 변환, 정상 Present 경로는 변경하지 않았다.
새 스레드, 라이브러리, 프레임 복사 또는 주기적인 로그 출력을 추가하지 않았다.
실행 파일은 621,568 → 622,592바이트로 **1KiB 증가**했다.
전체 입력 지연을 비교 실측한 것은 아니므로 수치상 동일 지연을 보증하지 않는다.

클린 Release 빌드에 성공했다. 로컬 RTX 3080에서 60회 출력 재생성/업로드/Present,
동시 모의 샘플 5,782건을 검사했고 D3D11 debug 경고·오류는 0이었다.
숨긴 창이라 60회 모두 occluded였다. 모니터 신호 전송이나 실제 캡처 하드웨어,
다른 GPU/드라이버의 장시간 사용을 검증한 것은 아니다.

- 전체 CTest: **20/20 통과**, 92.59초.
- 신규 기본 검사 5개: **각각 10회 반복 통과**.
- `git diff --check`: 통과.
- 기존 포터블 ZIP SHA-256 유지:
  `7C7058A660169EAE2E94CBDB4A26C8B8E54B9C9BC2028AB2422EB72A4A45EC41`.

## main.cpp: 더 나눌 필요가 있는가?

**선별적으로는 필요하지만, 지금 큰 덩어리를 이동시키는 작업은 권하지 않는다.**
현재 파일은 약 9,000줄이다. 설정 창 영역은 약 3,000줄, DirectD3D11Renderer는
약 1,100줄이며, 렌더러 안에서 직접 참조하는 서로 다른 `g_` 전역 이름은 21개다.
오디오 처리, 장치/형식 조회, 샘플 저장, 색상 처리, 설정 저장, 업데이트 등은 이미
별도 모듈이 있으므로 단순히 줄 수만 줄이는 추가 분리는 이익이 작다.

| 우선순위 | 후보 | 실질적인 이점 / 주의점 |
| --- | --- | --- |
| 1 | 출력 전환 상태 | 크기, 드래그, 전환 깊이, 갱신 보류를 한 상태 객체가 관리. 갱신 여부 판단 중복을 없애고 main.cpp 포함 없이 순수 상태 테스트 가능 |
| 2 | 설정 창 UI | 탭 구성/컨트롤 배치/가시성/메시지 처리의 변경 범위를 줄임. 장치 조회·검사 실행은 명시적 서비스 경계로 연결해야 하며 전역 extern 나열로 옮기면 이점이 작음 |
| 보류 | D3D11 렌더러 전체 | 설정, OSD, 볼륨, 색상 결과, 출력 세대가 얽혀 있음. 먼저 초기화 옵션과 표시 데이터의 입출력을 명시해야 함. 프레임마다 새 할당/불필요한 데이터 복사를 만드는 추상화는 피할 것 |
| 유지 | 실행 순서와 연결 부분 | 앱 시작/종료와 모듈 연결은 main.cpp의 역할. 작은 래퍼까지 무조건 다른 파일로 뗄 필요 없음 |

출력 전환 상태의 향후 경계는 `Begin/End`, 크기 변경, 드래그 시작/종료를 받아
‘출력 갱신 필요 여부’를 반환하는 작은 객체가 적절하다. UI 스레드에서만 상태를
바꾸고 기존 출력 세대 atomic으로 렌더러에 알리는 방식은 유지한다.
파일 분리만으로 지연이나 CPU 사용량이 좋아진다고 주장할 근거는 없다.

이번에는 **필요성과 분리 경계만 검토**했고 대규모 모듈 이동은 하지 않았다.
실제 모니터 ‘신호 없음’과 수정 사항의 인과관계는 여전히 미확인이다.

## 후속 작업: 실제 모듈화 — 2026-09-11

위의 검토 이후 사용자 요청으로 다음 두 경계를 실제로 분리했다. 여기부터가
현재 구현 상태이며, 앞 절의 '검토만 수행'은 이전 작업 시점을 설명한다.

### 분리한 책임

- `src/video/OutputTransitionState.h`: 클라이언트 크기, 수동 크기 조절,
  중첩 전환 깊이, 재생성 보류 상태를 한 객체로 관리한다. HWND/GPU/설정에
  의존하지 않고 출력 갱신 필요 여부만 반환한다. UI 스레드에서만 사용하며,
  main.cpp가 기존 atomic 세대 값을 갱신하는 연결 방식은 유지한다.
  수동 크기 조절 플래그 해제 → 창 크기 정규화 → 보류 요청 소비 순서도 유지했다.
- `src/ui/SettingsView.h/.cpp`: 컨트롤 핸들, 탭 종류, 배치, 폰트, 표시 조건,
  툴팁과 한영 도움말을 관리한다. 선택된 영상 포맷과 독점 모드 여부는 호출자가
  명시적으로 전달하며, 이 모듈에서 장치 검사·설정 저장·전역 상태 조회를 하지 않는다.
- `SettingsDialogState`는 UI 핸들 묶음을 기반으로 장치 목록/검사 결과/작업 스레드를
  계속 소유한다. 컨트롤과 폰트의 해제 시점, 작업 스레드 종료 순서를 바꾸지 않았다.
- D3D11 렌더러, 캡처/오디오 처리, 시작·종료 연결은 이번에 옮기지 않았다.
  의존성이 큰 렌더러를 전역 extern 나열로 옮기거나, 줄 수를 줄이기 위한
  production .inl 파일로 옮기는 방식은 사용하지 않았다.

main.cpp는 **9,003 → 8,405줄(-598줄)**이다. UI 레이아웃 좌표, 옵션 표시 조건,
도움말 문구와 정상 출력 루프는 유지했다. 시작 시점의 파일과 기계적으로 대조하여
예정한 분리/연결 변경 이외의 코드 변경이 없음을 확인했다.

### 검증

- Release 클린 빌드 성공. 이후 독립 모듈 테스트 두 개를 추가 빌드했다.
- 전체 CTest 최종 재실행: **22/22 통과**, 99.34초.
- `OutputTransitionStateTests`: 32개 난수 시드 × 100,000개 이벤트,
  총 **3,200,000개 상태 전환**을 분리 전 참조 로직과 비교하여 일치.
- `SettingsViewTests`: 한영 × 96/144/192 DPI × 4개 탭 × 5개 영상 포맷 ×
  Pixel-perfect/상대 크기/독점 여부 조합, 총 **960개 조합** 통과.
  기존 배치 74개 좌표, 볼륨 도움말 간격, F11 안내 z-order, HDR/MJPEG 조건부 표시,
  캡처 오디오 행 선택 보존, 공통 하단 컨트롤, 6개 툴팁 등록을 검사했다.
  도움말은 분리 전 문자열 해시와 비교했다. 초기 테스트의 영문 기준 해시 추출이
  문자열 안 세미콜론에서 끊기는 오류를 수정했고, 제품 도움말은 변경하지 않았다.
- 기존 WM_SIZE/F11/F5/수동 크기 조절 통합 테스트와 10,000개 난수 전환 시나리오를
  새 상태 객체에 연결한 뒤 재실행했다.
- 로컬 RTX 3080 숨긴 창에서 Flip 저지연/Flip VSync/Blt 출력 재생성·업로드·Present
  **60회**, 동시 모의 캡처 샘플 **7,137건**, D3D11 debug 경고·오류 **0건**.
  숨긴 창이라 60회 모두 occluded였으며 실제 모니터 신호/HDMI 검증은 아니다.

### 성능·배포 범위

새 스레드, 버퍼, 프레임 복사, 주기적인 작업, 라이브러리 의존성을 추가하지 않았다.
설정 뷰 호출은 설정창 이벤트에서, 출력 상태 판단은 기존 창 이벤트에서만 실행된다.
실행 파일은 **622,592 → 622,592바이트(변화 없음)**이다. 파일 분리로 속도가
향상되었다거나 실측 입력 지연이 완전히 같다고 주장하지 않는다.

테스트 소스/실행 파일은 사용자 배포 패키지에 넣지 않는다. 릴리스, 업로드,
커밋 및 기존 포터블 ZIP 교체는 하지 않았고, 기존 ZIP SHA-256도 동일하다.
다른 사용자 환경의 간헐적 모니터 '신호 없음' 해결 여부는 이번 검사로 확정할 수 없다.

## 후속 작업 2: 설정 컨트롤 생성과 공통 문구 분리 — 2026-09-11

사용자의 '문제 생기지 않고 필요한 선에서 계속' 요청에 따라 다음 단계만 진행했다.

- `src/ui/SettingsDialogControls.h/.cpp`: 설정 컨트롤 생성, 초기 옵션/체크 상태,
  장치 이름 목록 표시, ID 정의를 담당한다. 초기 설정은 const 참조, 장치/프리셋
  목록은 span으로 빌려 쓰므로 목록 전체를 복사하거나 새 소유권을 만들지 않는다.
- 출력 장치/버퍼/영상 포맷의 동적 채우기는 세 개의 명시적 동기 콜백으로 연결했다.
  호출 위치는 기존 WM_CREATE와 같다. 컨텍스트 포인터나 콜백은 보관하지 않으며,
  검사 스레드 시작/종료, 비동기 결과 소비 및 설정 저장은 기존 컨트롤러에 남겼다.
- `src/ui/UiText.h/.cpp`: 기존 공통 번역 사전을 그대로 이동했다. 언어는 인수로
  받고, 알려지지 않은 문구/한국어/null 처리와 번역 문자열 수명을 유지한다.
  기존 사전과 문자 단위로 일치하는 것을 확인했다. 문구 추가/번역 수정은 하지 않았다.
- `VideoPresetInfo` 형식은 UI 전용 형식이 아니라 앱 설정의 공통 데이터이므로
  `AppSettings.h`로 이동했다. 프리셋 값과 settings.ini 형식은 바꾸지 않았다.

main.cpp는 **8,405 → 7,563줄(-842줄)**이며, 두 차례 모듈화 전 9,003줄 대비
총 1,440줄 감소했다. 설정창 전체 제어기를 옮긴 것은 아니다. 메시지 라우팅,
장치 검사 수명 관리, 설정 적용/저장은 여전히 main.cpp에 있다.
렌더러나 오디오 처리까지 함께 이동하는 추가 변경은 이번 범위에 넣지 않았다.

### 검증 및 범위

- Release 클린 빌드 성공. main.cpp를 작업 시작 시점과 대조해 예정한 분리/
  어댑터 연결 이외의 변경이 없음을 확인했다.
- 실제 Windows 컨트롤 생성 테스트를 기존 SettingsViewTests에 추가했다.
  옵션 초기값, 원래 숫자 ID, ASIO 없는 환경의 선택 처리, 빈 장치 목록,
  캡처/오디오 장치 선택 복원, 툴팁 등록, F11 우측 정렬, 도움말 클릭의
  체크박스 독립성과 세 콜백의 호출 스레드/순서를 검사한다.
- 처음 60개 실제 창 생성 조합은 기본 60초 테스트 제한을 넘겼다. 직접 실행으로
  각 조합이 진행되는 것을 확인한 후, 같은 옵션 값/분기를 포함하는 24개 조합으로
  중복을 줄였다. 제품 코드를 바꿔 테스트 시간 제한을 회피한 것이 아니다.
- 기존 960개 배치/가시성 조합 및 도움말 원문 비교 검사는 그대로 유지했다.
- 직접 실행에서 60개 생성 사례도 모두 통과했다. 중복 축소 후 전체 CTest는
