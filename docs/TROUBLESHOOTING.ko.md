## 캡처 초기화 실패

OBS Studio, 제조사 캡처 프로그램, 브라우저, 화상 통화 앱, 가상 카메라 도구 등
캡처보드를 사용하고 있을 수 있는 프로그램을 모두 종료하세요. 일부 드라이버는
장치가 사용 중이라는 설명 대신 시스템 리소스 오류를 반환합니다.

그다음 아래 순서로 확인하세요.

1. USB 캡처보드는 다시 연결하고, PCIe 장치는 PC를 재시작합니다.
2. 입력 기기가 지원되는 progressive 해상도와 프레임을 출력하는지 확인합니다.
3. 자동 선택 대신 캡처 장치를 직접 선택합니다.
4. 자동/NV12, YUY2, 목록에 있다면 MJPEG 순서로 시험합니다.
5. 장치가 지원하는 더 낮은 해상도 또는 프레임을 시험합니다.
6. 진단 로그 파일 저장을 켜고 마지막 초기화 단계를 확인합니다.

`0x800705AA`는 Windows가 시스템 리소스 부족을 보고했다는 뜻입니다. 캡처보드에서는
다른 프로그램이나 제조사 서비스가 장치를 점유했거나 드라이버가 요청한 allocator를
거부했을 때도 나타날 수 있습니다.

`0x80070490`은 필요한 요소를 찾지 못했다는 뜻입니다. 요청 모드가 실제로 없거나,
호환되는 캡처 핀을 찾지 못했거나, 48kHz mono/stereo 비압축 PCM 또는 32-bit float
오디오 경로가 없는 경우가 대표적입니다. 오류 코드만 보는 것보다 로그의 실패 단계와
핀 진단이 중요합니다.

## 목록에 없는 30fps 요청이 실패함

**목록에 없는 FPS 요청**과 색상으로 구분된 30fps 표시는 지원을 보장하지 않습니다.
지원 여부는 **시작**을 눌러 드라이버에 요청한 뒤 확인합니다.

1. **40fps 캡처**가 켜져 있다면 끄고, 프레임에서 30fps를 선택했는지 확인합니다.
2. 실패하면 **목록에 없는 FPS 요청**을 끄고 자동 또는 기존에 작동하던 FPS로 재시도합니다.
3. 기본 모드가 작동하면 해당 해상도·포맷의 30fps 요청이 거부된 것일 수 있습니다.
   60fps가 된다고 30fps도 반드시 되는 것은 아닙니다. 실제 목록에 있는 다른 포맷만 비교하세요.

시작에 성공해도 **Tab → 실제 입력 FPS**를 확인하세요. 계속 문제가 있으면 장치명·해상도·포맷과 진단 로그를 보내주세요.

<br>

## 40fps 캡처가 시작되지 않음

**40fps 캡처**를 켜도 자동 인식 목록에 40fps가 추가되지는 않습니다. 목록에 없는
속도도 드라이버가 수락할 수 있지만, 체크박스가 활성화됐다는 것만으로 지원이
확인된 것은 아닙니다. **시작**할 때 요청 수락과 실제 연결 형식을 확인합니다.

1. 40fps 캡처를 끄고 원래 프레임 설정으로 재시도합니다.
2. 원래 설정은 된다면 해당 해상도·픽셀 포맷의 40fps 지원 여부를 확인합니다.
   다른 포맷은 드라이버가 목록에 제공하는 것만 선택하세요.
3. 계속 실패하면 진단 로그와 캡처 장치·해상도·포맷을 함께 전달해 주세요.

앱은 실패한 40fps를 60/120fps 등으로 자동 대체하지 않습니다. 시작에 성공해도
드라이버가 보고한 40fps와 실제 수신 속도는 별개이므로 Tab의 **실제 FPS**를 확인하세요.
콘솔의 HDMI 입력 Hz는 캡처보드 유틸리티에서 별도로 확인합니다.

<br>

## 재생이 중단되거나 입력이 사라짐

캡처 장치가 연결 끊김이나 입력 경로 오류를 보고하면 재생을 중단하고 재시작 안내
후 설정으로 돌아갑니다. 장치를 다시 연결하고 필요하면 다른 캡처 프로그램을
종료한 뒤 **시작**을 다시 선택하세요. 장치를 반복 검색하거나 캡처를 자동으로
재시작하지는 않습니다.

소스가 모든 캡처 스트림의 종료를 명시적으로 알리면 정상 종료로 처리하여 재생과
절전 방지 요청을 정리하고 설정을 다시 엽니다. 일시적인 무신호나 새 프레임이 잠시
오지 않는 상황만으로 재생을 끝내지는 않습니다. 입력 기기와 HDMI 연결을 확인하고,
입력이 복구되지 않으면 `F2`로 설정에 돌아가 모드를 확인한 뒤 직접 다시 시작하세요.

영상·오디오 형식 변경이 통보되어도 잘못된 출력을 막기 위해 재생을 중단할 수
있습니다. 재시작 전에 입력 기기의 HDR·해상도·오디오 설정을 확인하세요. 예상하지
못한 중단이 반복되면 진단 로그를 첨부해 주세요.

<br>

## 장치 또는 지원 모드 정보가 오래됨

영상·캡처 오디오·WASAPI Shared 지원 정보는 백그라운드에서 조회하고 설정 창이
열려 있는 동안 재사용합니다. 장치를 다시 연결하거나 드라이버·장치 설정을 바꿨다면
**새로고침**을 선택하고 조회 완료를 기다리세요. 필요한 영상 지원 정보를 조회
중이거나 조회에 실패한 상태에서는 시작할 수 없으며, 새로고침으로 실패한 조회도
다시 시도합니다. 재생 중 자동 반복 검색이 아닌 수동 설정 동작입니다.

ASIO 선택 중 새로고침해도 이전 WASAPI 장치의 Shared 지원 정보를 무효화하여
다시 전환할 때 갱신합니다. 이미 완료한 Exclusive 출력 장치 검사를 반복하지는
않습니다.

<br>

## 영상은 나오지만 소리가 없음

먼저 스피커 버튼의 음소거 상태와 마스터·L/R 음량을 확인하세요. **M**(기본값)으로
음소거를 해제할 수 있습니다. 백그라운드 자동 음소거를 켰다면 LLCV 창을 활성화하세요.

일부 USB 캡처보드는 영상과 오디오를 별도 DirectShow 필터로 제공합니다. **캡처
오디오 장치**에서 같은 USB 장치의 오디오 입력을 직접 선택하세요. 입력은 48kHz
mono/stereo 비압축 PCM 또는 32-bit float를 제공해야 합니다. 16-bit 스테레오 PCM은
변환 없는 직접 경로입니다.

별도 필터를 선택한 상태에서 장시간 사용한 뒤에만 소리가 끊긴다면 Tab 정보창의
PCM 추세를 관찰하고 클록 드리프트 보정을 시험하세요. 실행 직후부터 underrun이
반복된다면 먼저 PCM 목표를 한 단계 올리는 편이 맞습니다.

## 화면이 흐림

Pixel-perfect는 캡처 해상도를 그대로 사용할 수 있을 때 정확한 1:1 화면을
제공합니다. 크기가 바뀐 창이나 전체화면에서는 **선명하게**를 시험하세요. 지원되는
D3D11 Video Processor의 가장자리 보강을 사용하며 프레임 큐를 추가하지 않습니다.
드라이버가 지원하지 않으면 부드럽게로 자동 대체됩니다.

입력 기기의 출력 해상도와 캡처 해상도도 확인하세요. 1440p 입력을 4K로
캡처한다고 원본 세부 정보가 늘어나지는 않습니다.

<br>

## MJPEG 색이 다른 프로그램과 다름

MJPEG는 장치마다 Full/Limited 범위 또는 BT.601/709 정보를 생략하는 경우가
있습니다. 앱은 Media Foundation 디코더, DirectShow 메타데이터, MJPEG 기본값
순서로 자동 판정하며, 최종 연결된 캡처 형식의 색 정보도 재생·스크린샷·녹화에 반영합니다.
Tab 정보창의 **영상 품질**과 로그의
`[video] MJPEG color` 줄에서 실제 적용값을 확인하세요. 다른 프로그램과 계속
다르면 자동을 기준으로, 검정·흰색 명암은 **SDR 색 범위 → Limited / Full**을,
색상 자체는 MJPEG 선택 시 나타나는 **MJPEG 색 공간 → BT.709 / BT.601**을
확인하세요. 색 범위는 NV12/YUY2에도 적용되지만 P010/HDR에는 적용되지 않습니다.
맞는 설정이 없으면 같은 장면의 화면 캡처와 로그를 함께 전달해 주세요.

<br>

## 프레임 드랍 또는 끊김

40fps 캡처와 LS를 함께 사용 중이라면 먼저 LS와 40fps 옵션을 끄고 기존 캡처와 비교하세요.
40fps 또는 LS 3배 출력을 볼 때는 지원되는 모니터에서 120Hz로 맞춰 비교할 수
있습니다. 144Hz는 40의 정수 배수가 아니어서 고정 주사율에서 표시 간격이
고르지 않을 수 있습니다. 주사율을 맞춰도 원본 게임의 30~40fps 변동 자체가
사라지는 것은 아닙니다. [40fps 캡처 안내](VIDEO.ko.md#40fps-캡처)를 참고하세요.

Tab 정보창에서 입력 FPS가 선택한 소스 속도와 맞는지, Present FPS가 이를
따라가는지 확인하세요. YUY2나 MJPEG보다 NV12를 먼저 시험하고, 장치나 USB 연결이
현재 모드를 감당하지 못하면 해상도 또는 FPS를 낮춰 보세요.

서로 다른 주사율의 모니터와 Windows DWM 합성 때문에 창 모드 페이싱이 달라질
수 있습니다. 실제 사용할 모니터에서 저지연과 VSync를 비교하세요.

<br>

## 설정 창을 건너뜀

**다음 실행부터 바로 시작**이 켜져 있다면 실행할 때 Shift를 누르세요. 뷰어에서
`F2`를 눌러 안전하게 종료하고 설정 창으로 돌아갈 수도 있습니다.

<br>

## 단축키가 작동하지 않음

뷰어를 클릭해 LLCV에 초점을 맞추고, **도움말·진단**에서 지정한 키를 확인하세요.
키를 바꾼 뒤에는 **시작**을 눌러야 적용되며, **취소**하면 적용 전 변경은 버립니다.
설정창에서는 기본 입력·이동 키가 우선하고, 영상 전용 기능은 오디오 전용 모드에서
작동하지 않습니다.
설정 창의 도움말·녹화 단축키는 **F4를 제외한 기능키(F1~F24)** 또는 해당 키의 Ctrl·Alt·Shift 조합에
지정한 경우에만 작동합니다. 다른 키로 지정했다면 재생 창에 초점을 맞춰 사용하세요.

설정을 여는 키가 기억나지 않으면 **Shift**를 누른 채 앱을 실행하세요.
**기본값 복원 → 시작**으로 기존 단축키를 되돌릴 수 있습니다.
[단축키 변경 방법](USAGE.ko.md#단축키-변경)을 참고하세요.

<br>

## 설정을 저장하지 못함

설정 저장에 실패하면 이전 설정 파일은 보존되며, 저장하지 못한 변경 사항은 이번
실행에만 적용됩니다. 디스크 여유 공간과
`%LOCALAPPDATA%\LowLatencyCaptureViewer` 폴더 및 `settings.ini`의 쓰기 권한을
확인한 뒤 다시 저장하세요. 경고가 계속되면 표시된 오류 코드와 진단 로그를 함께
알려주세요.

<br>

## 절전 또는 화면 꺼짐 동작

**앱 → 재생 중 자동 절전 방지**는 기본 켜짐입니다. 영상 재생은 화면과 시스템을
유지하도록 요청하고, 오디오 전용 재생은 시스템만 유지하며 화면 꺼짐은 허용합니다.
재생 종료·오류·창 닫기 시 요청을 해제하며, 설정 창만 열려 있을 때는 PC를 깨워
두지 않습니다.

수동 절전, 덮개 닫기 동작과 Windows 전원 정책이 우선합니다. 절전 후 사용자가
돌아와 재생이 계속되면 요청을 다시 적용하지만, 사용자가 없는 자동 복귀에는
다시 적용하지 않습니다. Windows 전원 설정을 바꾸거나 화면 보호기·보안 잠금을
해제하는 기능은 아닙니다. 재생 중에도 일반적인 유휴 절전을 원하면 옵션을 끄세요.

<br>

## 문제 제보에 필요한 정보

**진단 로그 파일 저장**을 켜고 문제를 한 번 재현한 뒤 아래 폴더의 최신 파일을
첨부하세요.

```text
%LOCALAPPDATA%\LowLatencyCaptureViewer\logs
```

캡처보드 모델, 입력 해상도/FPS, 선택 포맷, 캡처 오디오 장치, 출력 장치,
Windows 버전과 다른 캡처 프로그램을 실행했는지도 함께 알려주세요.

## 녹화가 시작되지 않거나 중단됨

SDR 영상·스테레오 입력인지 확인하고 녹화 탭에서 지원되는 코덱·인코더·녹화 방식을 선택하세요.
**인코더 확인을 완료하지 못했습니다**가 표시되면 설정 창을 닫았다가 다시 열어 재시도하세요.
코덱 미지원과는 다른 상태이며, 검사가 끝나기를 기다리지 않고 설정 창을 닫아도 됩니다.
저장 공간과 폴더 쓰기 권한을 확인합니다. 과부하라면 녹화 해상도·프레임 상한을 낮추세요.
실패 시 안내의 파일 저장 여부를 확인하고, 비정상 종료 파일은 삭제하지 말고 호환 플레이어로 확인하세요.
[녹화 지원 범위와 파일 보호](RECORDING.ko.md)를 참고하세요.
