# 저지연 오디오

> [English](AUDIO.md) · [README로 돌아가기](../README.ko.md)

## 캡처 오디오 선택

자동 선택은 먼저 영상 캡처 필터 안에서 48kHz 스테레오 PCM 오디오 핀을
찾습니다. USB 캡처보드가 오디오를 별도 DirectShow 입력으로 제공하면 이름이
일치하는 장치를 자동으로 연결합니다. 자동 연결이 맞지 않을 때는 대응하는 오디오
입력을 직접 선택하세요.

서로 다른 필터에서 들어오는 영상과 오디오는 하드웨어 클록이 조금씩 다를 수
있습니다. 장시간 사용하면 이 차이로 PCM 대기량이 목표에서 벗어날 수 있습니다.
같은 클록을 쓰는 장치에서는 보정이 보통 필요하지 않지만, USB 영상·오디오 경로가
분리된 경우에는 도움이 될 수 있습니다.

## WASAPI Shared와 Exclusive

**WASAPI Shared**는 다른 프로그램도 출력 장치를 함께 사용할 수 있고 Windows의
Shared 모드 효과를 유지합니다. 기본 권장 방식입니다.

출력 장치가 `IAudioClient3`를 지원하면 유효한 Shared 엔진 주기를 읽고, 요청값과
가장 가까운 저지연 주기로 `InitializeSharedAudioStream` event-driven 출력을
시작합니다. 설정 창에는 지원 범위가, Tab 정보창에는 실제 적용 주기가 표시됩니다.

해당 장치나 포맷에서 `IAudioClient3`를 쓸 수 없으면 기존 WASAPI Shared로
자동 대체됩니다. 이는 정상적인 호환 경로이며 초기화 실패가 아닙니다.

**WASAPI Exclusive**는 출력 장치를 직접 엽니다. 공유 믹서 경로를 줄일 수 있지만
다른 프로그램이 해당 장치를 동시에 쓰지 못할 수 있습니다. Equalizer APO,
HeSuVi, Windows 공간 음향처럼 Shared 모드에 적용되는 APO/DSP도 우회할 수
있습니다. 이런 효과나 일반적인 호환성이 필요하면 Shared를 사용하세요.

## 출력 장치 전환

**Windows 기본 출력 장치 따라가기**를 사용하면 앱 실행 중 Windows 기본 장치를
바꿔도 영상 캡처를 유지한 채 WASAPI 출력만 다시 엽니다. 전환에 걸린 시간이
누적 재생 지연으로 남지 않도록 기존 PCM을 비우므로 짧은 무음이나 작은 클릭이
생길 수 있습니다.

Windows 기본 장치가 바뀌어도 항상 같은 장치로 출력해야 한다면 특정 출력 장치를
고정해서 선택하세요.

## WASAPI 버퍼와 PCM 목표

세 설정은 서로 다른 부분을 조절합니다.

- **WASAPI 출력 버퍼:** 출력 장치에 요청하는 period 또는 버퍼
- **PCM 버퍼 목표:** 캡처와 재생 사이의 앱 내부 안전 대기량
- **클록 드리프트 보정:** 장시간 샘플 속도 차이를 조절하며 위 두 버퍼를 대신하지 않음

PCM 목표는 10ms로 시작하세요. underrun이 반복될 때만 15/20/30ms로 올리는 것이
좋습니다. 목표를 높이면 스케줄링 여유가 늘지만 그만큼 오디오 대기 지연도
늘어납니다. 가끔 한 번 발생한 underrun은 반드시 들리는 문제이거나 버퍼를 올려야
한다는 뜻은 아닙니다.

로그에 표시되는 DirectShow allocator는 캡처 드라이버의 영향도 받습니다. 블록
크기나 개수가 앱이 실제로 쌓아 두는 오디오 양과 같지는 않습니다.

## 클록 드리프트 보정

보정을 끄면 PCM 샘플을 변경하지 않습니다. 장시간 사용 후 소리가 반복적으로
끊기거나 PCM 대기량 불균형이 한 방향으로 계속 커질 때, 특히 영상과 오디오가
별도 캡처 필터에서 들어올 때 보정을 켜세요.

보정은 PCM 대기량을 목표 부근에 유지하도록 샘플 속도를 아주 작게 연속 조절합니다.
별도 프레임이나 패킷 대기열을 의도적으로 추가하지 않습니다. 시작 직후나 순간적인
스케줄링 지연은 ppm 추정값을 왜곡할 수 있으므로 Tab 정보창을 10~30분 관찰한 뒤
판단하는 것이 좋습니다.

## 음량과 백그라운드 음소거

마우스 휠은 음량을 5% 단위로 바꿉니다. 100%에서는 PCM 볼륨 연산을 건너뜁니다.
**100% 이상 볼륨 증폭 허용**을 켜면 버퍼를 추가하지 않고 최대 200%까지 디지털
증폭하지만 큰 신호는 클리핑될 수 있습니다.

백그라운드 자동 음소거는 출력 게인만 변경합니다. 창이 비활성화되어도 캡처와
WASAPI 소비는 계속되므로 다시 돌아왔을 때 PCM 누적 지연이 생기지 않습니다.
