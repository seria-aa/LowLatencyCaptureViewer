# 영상 포맷, 확대와 전체화면

> [English](VIDEO.md) · [README로 돌아가기](../README.ko.md)

## 캡처 경로

DirectShow에서 영상을 받아 가장 최신 샘플만 유지하고, D3D11 Video Processor와
최대 프레임 지연을 1로 설정한 flip-discard 스왑체인으로 표시합니다. 오래된
샘플은 재생 대기열을 만들지 않고 버립니다.

Tab 정보창의 앱 처리 지연은 이 프로그램 내부 경로만 나타냅니다. 캡처보드,
입력 기기, Windows 화면 합성, 모니터 등에서 발생하는 HDMI 전체 지연은 포함하지
않습니다.

## 지원 모드 자동 인식

캡처 장치나 해상도를 바꾸면 픽셀 포맷과 프레임 목록을 다시 읽습니다. 첫 설정은
1920 x 1080에서 시작하며, 선택한 해상도는 저장됩니다. 설정 창이나 뷰어 창을
다른 모니터로 옮겨도 캡처 해상도가 자동으로 바뀌지는 않습니다.

자동 포맷은 비압축 NV12를 먼저, 그다음 YUY2를 선택합니다. 장치가 선택 해상도에서
제공한다고 알린 NV12, YUY2, P010과 MJPEG는 성능과 관계없이 모두 목록에
표시합니다. **MJPEG(실험적 압축 호환)**는 자동 선택에 포함되지 않으므로 필요한
경우 직접 선택해야 합니다.

H.264/AVC와 MPEG-4는 지원하지 않습니다. 프레임 간 참조와 디코더 재정렬 때문에
일관된 저지연 경로를 보장하기 어렵기 때문입니다.

## NV12, YUY2와 MJPEG

**NV12가 저지연 권장 포맷입니다.** 시스템 메모리에서 D3D11로 올릴 때 NV12는
픽셀당 12비트, YUY2는 16비트를 전송하므로 일반적으로 NV12의 대역폭과 처리
부하가 더 작습니다. 두 비압축 포맷은 이후 동일한 최신 프레임 전용 D3D11 Video
Processor 경로를 사용합니다.

YUY2는 4:2:2 색 정보를 유지하므로 색 세부 정보가 더 중요하거나 특정 장치가
YUY2를 더 잘 처리할 때 선택할 수 있습니다. 실제 차이는 캡처보드와 드라이버에
따라 달라집니다.

MJPEG는 Windows Media Foundation으로 디코딩하며 유용한 비압축 모드를 제공하지
않는 장치를 위한 호환 경로입니다. 앱이 별도 프레임 큐를 만들지는 않지만 장치
인코더와 디코더 경로 때문에 NV12/YUY2보다 지연이나 부하가 커질 수 있습니다.
디코더가 전달한 색 범위와 BT.601/709 행렬을 우선 적용하고, DirectShow 정보도
없으면 JPEG 관례에 따라 Full range로 처리합니다. 최종 적용값과 판정 출처는 Tab
정보창과 진단 로그에서 확인할 수 있습니다. 기본값인 **자동(권장)**으로 먼저
확인하고, 다른 앱과 색이 계속 다를 때만 MJPEG 선택 시 나타나는 **MJPEG 색상
해석**에서 BT.709/BT.601과 Full/Limited 조합을 직접 지정하세요. 이 옵션은
MJPEG에만 적용되며 NV12/YUY2에는 나타나거나 영향을 주지 않습니다.

## 프레임

입력 기기가 실제 출력하는 프레임을 선택하세요. 120fps 입력을 144fps로
캡처해도 새로운 영상 정보는 생기지 않으며 장치가 같은 프레임을 반복하거나
타이밍만 바꿀 수 있습니다. 120fps 입력은 120fps, 60fps 입력은 60fps, 30fps
입력은 30fps를 사용하는 것이 좋습니다.

장치가 정확한 30/29.97fps 미디어 타입을 제공하거나 지원 프레임 간격 범위에
포함하면 30fps가 목록에 나타납니다. 이를 선택하면 높은 프레임을 받은 뒤 버리는
것이 아니라 캡처 핀 자체를 해당 속도로 설정합니다. 앱의 대기열은 늘지 않지만
프레임 한 장의 간격이 33.3ms이므로, 같은 소스를 60/120fps로 안정적으로 받을 수
있다면 더 낮은 영상 지연과 부드러운 움직임을 기대할 수 있습니다.

입력 소스가 여러 프레임을 제공한다면 대상 모니터와 주기가 고르게 맞는 값이
VSync 페이싱에 유리할 수 있습니다. 예를 들어 120fps는 120Hz 또는 240Hz에서
균일합니다. 다만 모니터 주사율보다 소스의 실제 최대 프레임이 우선입니다.

## 화면 표시 방식

**저지연**은 추가 VSync 주기를 기다리지 않고 표시합니다. 가장 낮은 표시 지연을
기대할 수 있지만 화면 찢어짐이 보일 수 있습니다. **VSync**는 화면 동기를 기다려
찢어짐을 줄이는 대신 최대 한 주기 정도의 지연이 추가될 수 있습니다.

주사율이 서로 다른 모니터를 함께 쓰면 창을 옮길 때 Windows DWM 합성으로 프레임
페이싱이 달라지거나 미세한 스터터링이 생길 수 있습니다. 저지연 표시는 추가
VSync 대기를 줄이지만 DWM의 모든 차이까지 없애지는 못합니다. 실제 사용할
모니터에서 Tab 정보창의 입력 FPS와 Present FPS를 비교하세요.

## Pixel-perfect와 창 크기

**Pixel-perfect**를 켜면 클라이언트 영역이 캡처 해상도와 같은 1:1 크기로
고정되고 마우스 크기 조절이 꺼집니다. 끄면 영상 비율을 유지하면서 창 크기를
자유롭게 조절할 수 있습니다.

Pixel-perfect 전체화면은 캡처가 모니터 안에 들어가면 확대하지 않고 정확한
1:1로 중앙에 표시하며 남는 영역을 검게 채웁니다. 따라서 QHD와 FHD 입력은 모두
4K 모니터 중앙에 원본 크기로 표시됩니다. 캡처가 모니터보다 크면 자르지 않고
비율을 유지해 축소합니다.

`F5`는 저장된 Pixel-perfect 설정을 바꾸지 않고 정확한 1:1 창 크기를
복원합니다. 캡처와 모니터 해상도가 같으면 전체화면을 사용하며, 1:1 창이 모니터
작업 영역에 들어가지 않으면 HUD로 안내합니다. `F11`은 이와 독립적으로 보더리스
전체화면을 전환합니다.

전체화면 커서 기본값은 **자동 숨김**입니다. 포인터 입력이 2초 동안 없으면 숨기고,
마우스를 움직이거나 휠을 사용하면 즉시 다시 표시합니다. 커서를 계속 보이게 하려면
영상·창 탭에서 **항상 표시**를 선택하세요.

캡처와 모니터 해상도가 같으면 Pixel-perfect 설정과 관계없이 보더리스
전체화면으로 시작합니다. 단, 사용자가 더 작은 상대적 창 크기를 저장한 경우에는
의도한 창 크기를 우선해 다른 모니터에서 갑자기 전체화면이 되지 않게 합니다.

## 확대와 멀티 모니터

**화면 확대 방식**은 1:1이 아닐 때만 적용됩니다. 부드럽게는 기본 보간 방식이고,
선명하게는 드라이버가 지원할 경우 GPU Video Processor의 가장자리 보강을
사용합니다. 프레임 큐를 추가하지 않으며, 지원하지 않는 GPU에서는 부드럽게로
자동 대체됩니다.

**모니터 이동 시 상대적 창 크기 유지**는 해상도, DPI와 화면비가 다른 모니터
사이에서 영상 전체가 들어가는 축을 기준으로 비슷한 화면 점유율을 유지하고 다음
실행에도 복원합니다. 16:10 및 21:9/32:9 모니터에서도 영상 비율을 유지하며
불필요하게 한 번 더 축소하지 않습니다. Pixel-perfect와 독립된 옵션이므로 모니터
이동 후 1:1이 깨질 수 있습니다. 이때 `F5`를 누르면 정확한 크기로 다시 맞출 수
있습니다.

**제목 표시줄 숨기기**는 창 모드의 제목과 테두리를 제거합니다. 가장자리 스냅은
모니터 바깥 경계와 맞닿은 모니터 사이의 내부 경계에서 모두 작동합니다. 진입과
해제 거리는 DPI를 반영한 20 DIP이며, 드래그 중 Shift를 누르면 일시적으로
무시합니다.
