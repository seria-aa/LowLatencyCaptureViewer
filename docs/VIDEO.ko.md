## 캡처 경로

DirectShow에서 영상을 받아 가장 최신 샘플만 유지하고, D3D11 Video Processor와
기본적으로 최대 프레임 지연을 1로 설정한 flip-discard 스왑체인으로 표시합니다. 오래된
샘플은 재생 대기열을 만들지 않고 버립니다.

장치가 실행 중 다른 영상 형식이나 색 정보를 통보하면, 기존 방식으로 잘못 표시하지
않도록 재생을 중단하고 다시 시작하도록 안내합니다. 같은 형식의 재통보는 계속
재생합니다. 콘솔의 HDR·해상도 설정을 바꾼 뒤 이 안내가 나오면 캡처를 다시 시작하세요.
장치가 통보하지 않는 입력 변화까지 자동으로 감지하는 기능은 아닙니다.

장치 연결 끊김이나 입력 경로 오류가 보고되어도 재생을 중단하고 재시작 방법을
안내합니다. 장치를 자동으로 반복 검색하거나 다시 연결하지는 않습니다. 모든 캡처
스트림의 종료가 명시적으로 통보되면 설정으로 돌아가고 절전 방지 요청을 해제합니다.
일시적인 무신호만으로 스트림 종료로 처리하지는 않습니다.
[재생 중단 문제 해결](TROUBLESHOOTING.ko.md#재생이-중단되거나-입력이-사라짐)을 참고하세요.

Tab 정보창의 앱 처리 지연은 이 프로그램 내부 경로만 나타냅니다. 캡처보드,
입력 기기, Windows 화면 합성, 모니터 등에서 발생하는 HDMI 전체 지연은 포함하지
않습니다.

## 지원 모드 자동 인식

다중 입력 WDM 장치 중 해당 구조를 사용하는 경우, 설정의 모드 조회와 재생 시작에서 영상 핀을
사용하기 전에 상위 크로스바를 연결합니다. 설정 조회에는 실행하지 않는 임시 그래프를 사용합니다.
기존 물리 입력 선택을 유지하며 HDMI·컴포넌트 입력을 자동으로 고르는 기능은 아닙니다.
명확한 오디오 핀은 제외하고 입력 구조를 구분할 수 없으면 추측하지 않고 로그를 남깁니다.
연결 실패 시 새로 추가한 필터를 정리하며, 그래프를 복구하지 못하면 재생 시작이나 모드 조회를
중단합니다.

캡처 장치나 해상도를 바꾸면 백그라운드 조회와 캐시된 결과로 픽셀 포맷과 프레임
목록을 갱신합니다. 설정 창이 열려 있는 동안 결과를 재사용하며, 장치나 드라이버가
바뀌었다면 **새로고침**으로 장치·지원 정보를 다시 조회하세요. 필요한 영상 지원
정보를 조회 중이거나 조회에 실패한 상태에서는 시작할 수 없습니다.

첫 설정은 1920 x 1080에서 시작하며, 선택한 해상도는 저장됩니다. 설정 창이나 뷰어 창을
다른 모니터로 옮겨도 캡처 해상도가 자동으로 바뀌지는 않습니다.

자동 포맷은 비압축 NV12, YUY2, UYVY/HDYC 순서로 선택합니다. 장치가 선택 해상도에서
제공한다고 알린 NV12, YUY2, UYVY/HDYC, P010, MJPEG, RGB24와 XRGB (RGB32)는 성능과 관계없이 모두 목록에
표시합니다. **MJPEG(압축 호환)**는 자동 선택에 포함되지 않으므로 필요한
경우 직접 선택해야 합니다.

H.264/AVC와 MPEG-4는 지원하지 않습니다. 프레임 간 참조와 디코더 재정렬 때문에
일관된 저지연 경로를 보장하기 어렵기 때문입니다.

## RGB24와 XRGB (RGB32)

장치가 선택한 해상도·FPS에서 제공하는 RGB SDR 입력을 직접 선택할 수 있습니다.
자동 선택은 기존 NV12 → YUY2 → UYVY/HDYC 순서를 유지합니다.
RGB24는 BGR 24비트, XRGB는 BGRX 32비트 입력이며 X 값은 무시합니다.
영상의 상하 방향과 SDR 색 범위 설정은 재생·원본 스크린샷·녹화에 일관되게 반영합니다.

RGB24는 GPU에서 표시용 형식으로 재배열하며, XRGB는 기존 비디오 처리기로 전달합니다.
NVIDIA VSR을 선택할 수 있으며 CMAA2→NIS와 중복 적용하지 않습니다.
입력 형식에 따라 VSR 효과가 다르게 보일 수 있고, 요청 성공이 실제 효과 활성화를 보장하지는 않습니다.
RGB 원본 PNG에는 VSR·OSD가 포함되지 않습니다.

RGB 녹화는 작업 스레드에서 BT.709 Limited NV12(4:2:0)로 변환합니다.
부하 검사·메모리 제한은 [녹화 안내](RECORDING.ko.md)를 참고하세요.
RGB 캡처·녹화는 SDR 전용이며 HDR 콘솔을 RGB로 캡처하는 우회 방식은 지원하지 않습니다.
일반적인 저지연 사용에는 계속 NV12를 권장합니다.

<br>

## NV12, YUY2와 MJPEG

**UYVY / HDYC(8비트 4:2:2)** 입력도 재생과 원본 스크린샷을 지원합니다.
기존 업로드 텍스처에서 GPU가 바이트 순서만 YUY2로 바꾸며 캡처 원본은 수정하지 않습니다.
HDYC는 색 정보가 없으면 BT.709를 기본값으로 사용하고, 명시된 장치 색 정보와 사용자
SDR 색 범위 설정은 유지합니다. **UYVY/HDYC 녹화는 지원하지 않습니다.** 녹화하려면
NV12·YUY2·MJPEG 입력을 선택하세요. Blackmagic 전용 DeckLink SDK가 아닌 DirectShow를
사용하므로, 장치 이름이 표시되어도 모든 해상도에서 호환되는 영상 형식을 제공한다는
뜻은 아닙니다. v210(10비트 4:2:2) 입력은 지원하지 않습니다.

**NV12가 저지연 권장 포맷입니다.** 시스템 메모리에서 D3D11로 올릴 때 NV12는
픽셀당 12비트, YUY2는 16비트를 전송하므로 일반적으로 NV12의 대역폭과 처리
부하가 더 작습니다. 두 비압축 포맷은 이후 동일한 최신 프레임 전용 D3D11 Video
Processor 경로를 사용합니다.

YUY2는 4:2:2 색 정보를 유지하므로 색 세부 정보가 더 중요하거나 특정 장치가
YUY2를 더 잘 처리할 때 선택할 수 있습니다. 실제 차이는 캡처보드와 드라이버에
따라 달라집니다.

MJPEG는 Windows Media Foundation으로 디코딩하며 유용한 비압축 모드를 제공하지
않는 장치를 위한 호환 경로입니다. 앱이 별도 프레임 큐를 만들지는 않지만 장치
인코더와 디코더 경로 때문에 NV12/YUY2보다 지연이나 부하가 커질 수 있습니다.
디코딩 버퍼를 재사용해 반복 할당을 줄입니다. 최신 프레임 우선 정책은 유지하며,
모든 장치에서 실제 전체 지연이 줄어든다는 보장은 아닙니다.
최종 연결에서 전달되는 색 정보는 재생·스크린샷·녹화에 동일하게 반영하며, 뒤의
형식에서 생략한 정보는 앞서 전달된 값을 유지합니다.

**SDR 색 범위**는 **자동 / Limited / Full** 중 선택하며 자동을 권장합니다. 기본값인 자동은
기존 판정을 유지합니다. NV12/YUY2는 장치 정보가 없으면 Limited, MJPEG는 디코더
정보와 DirectShow 정보를 차례로 확인하고 둘 다 없으면 Full로 처리합니다.
검정이 뭉개지거나 화면이 뿌옇게 보일 때만 실제 캡처 데이터에 맞춰 수동 지정하세요.
HDMI 출력 범위를 바꾸거나 이미 손실된 명암을 복원하는 기능은 아니며, **P010/HDR에는
적용하지 않습니다.** 최종 적용값과 판정 출처는 Tab 정보창과 진단 로그에서 확인합니다.

MJPEG 선택 시 **MJPEG 색 공간**에서 **자동 / BT.709 / BT.601**을 별도로 선택할 수
있습니다. 색 범위 선택은 위 항목으로 통합되어 중복되지 않습니다. 색 공간 자동은
디코더·장치 정보를 우선하고, 없으면 HD는 BT.709, SD는 BT.601을 사용합니다.
기존 MJPEG 수동 보정값은 유지하며, 새 색 범위를 직접 선택하면 공통 설정을 따릅니다.

## 프레임

30/60fps 등 프레임을 직접 선택하면 다른 FPS로 자동 대체하지 않습니다. 자동 포맷도
선택한 FPS를 지원하는 포맷 안에서 고릅니다. 장치가 다른 FPS를 반환하면 시작을
중단하고 안내합니다. **자동**은 기존 포맷 우선순위와 지원 모드 선택을 유지합니다.
조회·해상도·포맷 변경 후 선택값이 지원되지 않으면 **지원 안 됨**으로 보존하며,
다른 FPS나 포맷을 직접 고르기 전에는 시작하지 않습니다.

이 설정은 캡처 속도 요청이지 LS 생성 프레임의 상한이 아닙니다. **Tab → 실제 FPS**의
입력·Present로 구분하세요. 장치가 정상 FPS로 보고하면서 실제로 더 많이 보내는
상태가 지속되면 진단창과 로그에 경고합니다. 경고 때문에 대기나 프레임 제한을
추가하지는 않습니다.

영상 설정의 **프레임 → 추가 설정**에서 목록에 없는 FPS 요청과 40fps 캡처를
선택합니다. Esc 또는 닫기를 누르면 추가 설정만 닫히며 선택값은 유지됩니다.
설정 창 전체의 취소는 기존처럼 변경을 적용하지 않습니다.
SDR 색 범위는 픽셀 포맷 아래에 있으며, MJPEG 색 공간과 HDR 옵션은 해당
형식을 선택했을 때만 나타납니다. 작은 화면에서는 기존 항목별 페이지를 사용합니다.

입력 기기가 실제 출력하는 프레임을 선택하세요. 120fps 입력을 144fps로
캡처해도 새로운 영상 정보는 생기지 않으며 장치가 같은 프레임을 반복하거나
타이밍만 바꿀 수 있습니다. 120fps 입력은 120fps, 60fps 입력은 60fps, 30fps
입력은 30fps를 사용하는 것이 좋습니다.

장치가 정확한 30/29.97fps 미디어 타입을 제공하거나 지원 프레임 간격 범위에
포함하면 30fps가 목록에 나타납니다. 이를 선택하면 높은 프레임을 받은 뒤 버리는
것이 아니라 캡처 핀 자체를 해당 속도로 설정합니다. 앱의 대기열은 늘지 않지만
프레임 한 장의 간격이 33.3ms이므로, 같은 소스를 60/120fps로 안정적으로 받을 수
있다면 더 낮은 영상 지연과 부드러운 움직임을 기대할 수 있습니다.

입력 소스가 여러 프레임을 제공한다면 대상 모니터와 주기가 고르게 맞는 값이
VSync 페이싱에 유리할 수 있습니다. 예를 들어 120fps는 120Hz 또는 240Hz에서
균일합니다. 다만 모니터 주사율보다 소스의 실제 최대 프레임이 우선입니다.

### 목록에 없는 30fps 요청

**영상 → 목록에 없는 FPS 요청**을 켜고 **프레임 → 30fps**를 선택한 뒤 **시작**을 누르세요.
기본값은 꺼짐입니다. QHD에만 적용되는 기능이 아니며, 선택한 해상도·픽셀 포맷을 기준으로 요청합니다.

자동 인식 아래에 다른 색으로 표시되는 **직접 요청: 30fps**는 드라이버가 지원을 확인했다는 뜻이 아닙니다.
드라이버가 거부하거나 연결된 형식이 다른 FPS이면 안내하고 시작을 중단합니다.
시작한 뒤에도 **Tab → 실제 입력 FPS**를 확인하세요. 60fps 입력을 앱에서 30fps로 줄이는 기능은 아닙니다.

옵션을 끄면 추가된 30fps 선택은 자동으로 돌아갑니다. 드라이버가 원래 제공한 30fps는 그대로 남습니다.
**40fps 캡처**가 켜져 있으면 40fps를 우선 요청하므로, 30fps를 쓰려면 먼저 해제하세요.
모든 장치·모드에서 작동하는 것은 아닙니다. [시작 실패 시 확인](TROUBLESHOOTING.ko.md#목록에-없는-30fps-요청이-실패함)

<br>

### 40fps 캡처

영상 설정의 **프레임 옆 추가 설정 → 40fps 캡처**는 기본 꺼짐입니다. 체크하면 기존 프레임
선택 대신 캡처 드라이버에 40fps를 요청하고, 해제하면 기존 선택으로 돌아갑니다. 자동 인식
목록에는 임의로 40fps를 추가하지 않습니다. 목록에 없는 속도도 드라이버가 수락할
수 있지만, 장치·해상도·픽셀 포맷별 지원은 다릅니다. 드라이버가 거부하거나 실제
연결 형식을 40fps로 보고하지 않으면 다른 속도로 대체하지 않고 시작 오류를
안내합니다. 체크만으로 장치를 열어 시험하지는 않으며, **시작**할 때 확인합니다.
드라이버의 형식 보고와 실제 수신 속도는 다를 수 있으므로 Tab의 실제 입력 FPS도 확인하세요.

이 옵션은 지원되는 해상도·포맷 조합에서 캡처 속도만 요청합니다. NV12·YUY2·P010·
MJPEG 중 어떤 조합이 40fps를 수락할지는 드라이버에 따라 다릅니다. 앱이 소프트웨어로
프레임을 보간하거나 더 빠른 스트림을 40fps로 변환하지 않습니다.
40fps의 프레임 간격은 25ms이므로 60/120fps 캡처보다 입력 반영이 늦어질 수 있습니다.
이 옵션 자체가 지연을 줄이거나 움직임을 더 부드럽게 만드는 것은 아닙니다.

일반적인 시청에는 기존 프레임 설정을 유지하세요. 40fps 게임도 지원되는 120Hz
출력을 120fps로 캡처해 볼 수 있으므로, 게임이 40fps라는 이유만으로 이 옵션을
켤 필요는 없습니다. 특정 캡처 속도가 필요한 경우에만 사용하세요.

30~40fps 가변 게임을 고정 40fps로 캡처하면 고유 프레임 누락 없이도 같은 화면이
25ms 또는 50ms씩 유지되는 등의 반복이 생길 수 있습니다. 게임을 40fps로 고정하거나
VRR을 대체하는 기능이 아닙니다. 앱의 **도움말·진단 → 40fps 캡처 안내**에서도
기본 동작과 주의사항을 확인할 수 있습니다.

#### 활용 예시: Lossless Scaling

외부 프레임 생성 앱에 40fps 입력을 전달하려는 경우의 예시입니다. LLCV의 LS
연동 기능이나 필수 사용 조합을 뜻하지 않습니다.

**안정적인 40fps를 유지하는 게임을 전제로 합니다.** 30~40fps로 흔들리면 반복
프레임 때문에 LS를 써도 끊김이 남거나 더 두드러질 수 있습니다.

콘솔의 40fps 게임 모드는 지원되는 경우 HDMI 출력을 120Hz로 설정하고 캡처보드의
입력 정보에서도 확인하세요. HDMI 120Hz가 게임의 고유 120프레임을 뜻하지는 않습니다.
60Hz 신호는 균일한 40fps 움직임을 그대로 전달할 수 없습니다.

[Lossless Scaling](https://store.steampowered.com/app/993090/Lossless_Scaling/)은
별도 앱이며 LLCV에 내장되지 않습니다. 사용하려면 GPU 성능에 여유를 두고 LLCV 창에
프레임 생성을 적용합니다. 예를 들어 40fps의 3배는 120fps이므로 표시 모니터를 120Hz로
맞춰 비교할 수 있습니다. LLCV는 모니터 주사율이나 LS 설정을 자동 변경하지 않습니다.

LS는 추가 지연·화면 왜곡이 생길 수 있고, 실제 게임과 LS 조합의 결과는
보장하지 않습니다. 더 끊기면 이 옵션과 LS를 끄고 기존 캡처와 비교하세요.

## 화면 표시 방식

**저지연 (일반 출력)**과 **저지연 (독점 전체화면)** 모두 추가 VSync 대기 없이
표시하는 방식입니다. 일반 출력은 창·보더리스 전체화면에서 다른 앱과 함께 쓰기 편하며,
기본값입니다. 독점 전체화면은 환경에 따라 표시 지연을 더 줄일 수 있지만,
독점 상태에서는 같은 화면에 다른 창을 함께 띄울 수 없습니다.

**저지연 (독점 전체화면)**은 전체화면에서 출력 독점을 요청하며 Alt+Tab이나
설정·안내창을 열면 해제하고 복귀 시 다시 요청합니다. 실패하면 창 출력으로 돌아갑니다.
OSD·HDR·VSR은 기존 지원 조건을 따릅니다. 다른 창을 함께 쓰려면 저지연 (일반 출력)을
사용하세요. 모든 환경에서 직접 표시나 일정한 지연 감소를 보장하지 않습니다.


두 저지연 방식 모두 화면 찢어짐이 보일 수 있습니다. **VSync**는 화면 동기를 기다려
찢어짐을 줄이는 대신 최대 한 주기 정도의 지연이 추가될 수 있습니다.

Flip **VSync**에서는 스왑체인이 받을 준비가 된 다음 최신 캡처 프레임을 가져와 업로드합니다.
그동안 캡처는 최신 한 장만 유지하며 장치 오류·종료·전원 알림도 계속 처리합니다. 준비 신호를
사용할 수 없거나 입력이 준비된 상태에서 2초간 신호가 없으면 로그를 남기고 기존 표시 경로로
돌아가며 설정값은 바꾸지 않습니다. 기본 저지연·독점 전체화면·호환성 경로에 대기를 추가하는
변경이 아니며, 실측된 지연 개선 수치를 뜻하지는 않습니다.

주사율이 서로 다른 모니터를 함께 쓰면 창을 옮길 때 Windows DWM 합성으로 프레임
페이싱이 달라지거나 미세한 스터터링이 생길 수 있습니다. 저지연 표시는 추가
VSync 대기를 줄이지만 DWM의 모든 차이까지 없애지는 못합니다. 실제 사용할
모니터에서 Tab 정보창의 입력 FPS와 Present FPS를 비교하세요.

**호환성 출력(Blt · VSync)**은 저지연·VSync의 Flip 출력과 다른 스왑체인 경로를 사용합니다.
지연과 GPU 부하가 늘 수 있으며 HDR10 출력은 지원하지 않습니다.
캡처와 오디오 버퍼는 바꾸지 않습니다.

**표시 모니터**는 시작 위치를 선택합니다. 자동은 마지막 위치를 복원하고,
직접 지정하면 해당 모니터에서 시작합니다. 미연결 시 주 모니터를 사용합니다.
창이나 GPU 출력 경로를 고정하는 기능이 아니므로 실행 후에도 창을 옮기거나
현재 모니터에서 F11을 사용할 수 있습니다.

### OBS와 독점 전체화면 비교

2026-10-17 테스트 PC에서 측정한 참고 결과입니다. 동일 프레임의 **소스 표시 이벤트부터
뷰어 표시 이벤트까지** Windows ETW로 비교했으며 HDMI·캡처 전달 구간을 포함합니다.
카메라·광센서로 측정한 물리적인 입력 지연이나 Tab의 앱 처리 지연과는 다른 값입니다.

| LLCV 표시 방식 | OBS 평균 지연 | LLCV 평균 지연 | OBS 대비 감소 |
| --- | ---: | ---: | ---: |
| 일반 창 | 32.9ms | 27.9ms | 5.0ms |
| 보더리스 전체화면 | 33.3ms | 27.6ms | 5.7ms |
| 독점 전체화면 | 33.3ms | **11.4ms** | **21.9ms** |

OBS 32.2.2는 일반 창 행에서 창 프로젝터, 전체화면 두 행에서 같은 전체화면
프로젝터 결과를 기준으로 비교했습니다. OBS의 독점 전체화면을 측정한 값은 아닙니다.
GC573으로 2560×1440 120fps NV12 SDR을 캡처해 같은 3840×2160 144Hz 모니터에
표시했습니다. 일반 창은 영상 영역 1280×720, 전체화면은 3840×2160입니다.
출력 크기도 달라지므로 행 사이의 차이를 창 테두리 유무만의 효과로 해석할 수 없습니다.

VSR·OSD·녹화는 껐고, OBS는 120fps 구성·캡처 버퍼링 끄기·메인 미리보기 끄기로
설정했습니다. 각 2회, 회당 안정 구간 25초에서 대응된 프레임을 합산한 평균입니다.
일반 창은 OBS 5,811개·LLCV 5,921개, 전체화면은 OBS 5,420개·LLCV 보더리스
6,000개·독점 5,220개를 비교했습니다.

**해석 시 주의:** 같은 GPU가 HDMI 테스트 영상을 생성하고 뷰어도 실행했습니다.
양쪽 일부 회차에서 고유 프레임 누락이 있었으며, 평균은 대응된 표시 프레임만 대상으로 합니다.
소스 쪽 누락도 확인됐지만 나머지 누락 원인은 분리하지 못했습니다. 이 차이는 비교값에
영향을 줄 수 있으므로 무손실 재생이나 항상 21.9ms 빠르다는 의미가 아닙니다.
OBS의 모든 출력 방식·설정에 일반화할 수 없으며, 오디오 지연·싱크 비교도 아닙니다.

## P010 HDR10

HDR로 보려면 캡처 입력뿐 아니라 **앱을 표시하는 모니터의 Windows HDR**도
켜져 있어야 합니다. 패스스루 모니터가 HDR이라는 사실만으로 PC 화면까지
HDR인 것은 아닙니다. Tab 정보창은 앱의 PQ 출력과 현재 화면의 HDR 상태를
구분해 표시합니다. 화면 SDR 또는 확인 불가 안내가 나오면 먼저 Windows와
모니터 설정을 확인하세요. 모니터 이동과 HDR 설정 변경은 주기적으로 다시 확인합니다.

- 지원 경로는 **P010 · BT.2020 · PQ · Limited → Flip HDR10**입니다.
  색차 위치는 입력 정보에 따라 left/top-left로 처리합니다.
- P010은 **HDR 전용**입니다. SDR로 보고된 입력을 SDR P010으로 표시하지 않고
  안내와 함께 차단합니다. SDR은 NV12/YUY2를 선택하세요.
- 연결 후 확정된 색 정보를 사용합니다. PQ가 확인되었지만 일부 정보가 빠진
  경우 HDR10 기본값을 사용하고 그 가정을 로그에 기록합니다.
- 전달 함수·색역 정보가 없는 P010은 OBS의 DirectShow P010 기본값처럼
  **PQ/BT.2020 HDR10으로 가정**합니다. 실제 HDR 감지에 성공했다는 뜻은 아니며,
  그 가정은 로그에 구분해 기록합니다. 명시적인 SDR/HLG 정보나 불완전한
  BT.2020 정보는 이 기본값으로 덮어쓰지 않고 색 범위·색차 배치도 계속 검증합니다.
- **HDR10 강제**는 입력이 실제 PQ/BT.2020인데 장치의 색 정보가 틀리거나 불완전한
  경우에만 사용하세요. SDR을 HDR로 바꾸는 기능이 아닙니다.
- P010을 선택하면 HDR10 강제 아래에 **HDR 색차 배치**가 표시됩니다.
  평소에는 **자동(권장)**으로 두세요. **Top-left**와 **Left**는 색차 배치 정보가
  없거나 잘못된 장치를 위한 수동 호환성 해석입니다. 가는 색 경계와 글자를
  기준 화면과 비교하세요. 영상이 열린다고 배치가 정확하다는 뜻은 아니며,
  실제로 어긋난 색차 데이터를 복원하거나 HDR 색 범위 검증을 바꾸지는 않습니다.
- HLG, Full-range HDR 및 Blt HDR은 지원하지 않으며 임의의 SDR 변환으로
  대신하지 않습니다. 색 정보가 없는 SDR 소스는 NV12/YUY2를 선택하세요.
  HDR10 강제를 꺼도 정보가 없는 P010의 HDR 기본 가정은 유지됩니다.
- 원본에 없는 최대 밝기/마스터링 정보를 만들어 보내지 않고, 영상 PQ 값은
  보존합니다. 모니터에 맞춘 자체 HDR→SDR **재생 화면** 톤매핑은 제공하지 않습니다.
  [스크린샷 저장](USAGE.ko.md#스크린샷)은 별도로 SDR sRGB 톤매핑을 사용합니다.
- HDR 위의 OSD는 Windows의 SDR UI 밝기를 참고해 선형 광량으로 합성합니다.
  조회가 불가능하면 203nit 기준을 사용합니다. 이 보정은 영상 밝기를 바꾸지 않습니다.
- HDR `Tab` 정보창 배경은 **검정·불투명도 90%**로 표시합니다.
  배경 영상 광량의 약 10%가 비치며, 글자 밝기 기준과 SDR 정보창 모양은 유지합니다.

캡처보드가 전달하는 실제 데이터와 모니터의 톤매핑에 따라 패스스루와 밝기가
다를 수 있습니다. 실제 HDR 장치에서의 최종 밝기·색 정확도 검증은 아직 필요하며,
이 구현만으로 모든 기기의 일치를 보장하지 않습니다.

### 캡처보드 내부 톤매핑

지원되는 AVerMedia·Elgato 장치에는 캡처 시작 시 한 번, P010은 내부 HDR→SDR
톤매핑 **끔**, NV12/YUY2/MJPEG는 **켬**을 요청합니다. 일반 드라이버 제어는
모델 이름만으로 판단하지 않고 선택한 필터의 전용 명령 지원을 확인합니다.
AVerMedia USB 확장 제어는 해당 노드의 응답을 검증한 뒤 요청합니다.
P010 자체가 실제 HDR 신호임을 보장하는 것은 아닙니다.

지원하지 않거나 명령이 실패해도 캡처는 계속하며, 결과는 로그의
`[capture-hdr]`에 기록합니다. 명령 수락은 실제 HDR 전달 확인과 다릅니다.
이 기능을 위해 프레임 대기나 영상 처리 단계를 추가하지는 않습니다.

Elgato USB/HID는 공개 프로토콜이 확인된 HD60 S+, HD60 X, HD60 X Rev.2의
장치 ID만 대상으로 합니다. Windows 장치 식별 정보로 선택한 비디오 장치와
같은 물리적 기기인지 확인하고, 대상이 모호하면 건너뜁니다. 다른 모델이나
제조사에 확인되지 않은 명령을 보내지는 않습니다. 이 범위는 모든 카드의
실기기 호환성 보증이 아니며, 캡처 앱 여러 개의 동시 장치 사용도 피하세요.

## Pixel-perfect와 창 크기

**캡처 해상도**와 **표시 해상도**는 VSR과 관계없이 별도로 선택합니다.
표시 해상도를 **캡처 해상도와 동일**로 두면 캡처 해상도를 변경할 때 표시 크기도 함께 따라갑니다.
새 설정의 기본값입니다. 업데이트 이전 캡처·표시 크기가 같으면 자동 연동으로 이전하고,
서로 다르면 기존 고정 크기를 유지합니다. 새 버전에서 직접 저장한 고정/연동 선택은 우선합니다.
**Pixel-perfect / 표시 크기 고정**은 선택한 표시 크기로 창을 고정합니다.
입력·표시 해상도가 같을 때만 원본 1:1이며, 끄면 비율을 유지해 창을 조절할 수 있습니다.
F6은 선택한 업스케일링 방식과 선명도를 유지하면서 켜고 끄며, F5는 입력 크기로 복원합니다.

창 크기를 바꿀 때는 필요한 영상 출력 자원만 갱신하고, 창 크기에 무관한 자원은
재사용해 재생성 비용을 줄입니다. 캡처 해상도나 버퍼링을 바꾸는 기능은 아니며,
실측 지연 개선을 보장하지 않습니다.

보더리스·독점 전체화면은 선택한 표시 해상도를 유지하고 남는 영역을 검게 채웁니다.
예를 들어 4K 모니터에서 1920×1080을 선택하면 영상은 1080p 크기로 표시됩니다.
**창 → 전체화면 영상 위치**에서 중앙·위·아래·좌·우 및 모서리 위치를 고릅니다.
선택한 크기가 화면보다 크면 잘리지 않도록 비율을 유지해 축소합니다.

`F5`는 저장된 Pixel-perfect 설정을 바꾸지 않고 정확한 1:1 창 크기를
복원합니다. 캡처와 모니터 해상도가 같으면 전체화면을 사용하며, 1:1 창이 모니터
작업 영역에 들어가지 않으면 HUD로 안내합니다. `F11`은 이와 독립적으로 보더리스
전체화면을 전환합니다. 독점 표시 방식에서는 독점 전체화면을 사용합니다.

전체화면 커서 기본값은 **자동 숨김**입니다. 포인터 입력이 2초 동안 없으면 숨기고,
마우스를 움직이거나 휠을 사용하면 즉시 다시 표시합니다. 커서를 계속 보이게 하려면
**창** 페이지에서 **항상 표시**를 선택하세요.

캡처와 모니터 해상도가 같으면 Pixel-perfect 설정과 관계없이 보더리스
전체화면으로 시작합니다. 단, 사용자가 더 작은 상대적 창 크기를 저장한 경우에는
의도한 창 크기를 우선해 다른 모니터에서 갑자기 전체화면이 되지 않게 합니다.

## 확대와 멀티 모니터

**영상 → 업스케일링**에서 **끄기 / CMAA2 → NIS / NVIDIA VSR**을 선택합니다.
CMAA2 → NIS는 SDR 원본의 계단현상을 보정한 뒤 가로·세로 최대 2배로 확대하며,
선명도 기본값은 **0.15**입니다. 기본 꺼짐이고 VSR과 동시에 적용하지 않습니다.
SDR의 CMAA2 보정은 높음·보존형을 선택할 수 있습니다. P010 HDR10은 NIS와
원본 기준 윤곽 보호를 사용하며 CMAA2 보정 선택은 SDR용으로 유지합니다.
선명도 목록은 0.00·0.10·0.15·0.20·0.30·0.50·1.00으로 간소화했습니다.
목록에 없는 기존 저장값은 별도 항목으로 유지하며 임의로 반올림하지 않습니다.
원본 크기·축소·2배 초과 확대에서는 기존 출력 경로를 사용합니다.
표시 해상도가 캡처와 같으면 먼저 표시 크기를 높이세요.
녹화·스크린샷은 이 보정의 영향을 받지 않으며 OSD는 처리 뒤에 표시합니다.
[선택 방법과 동작 조건](USAGE.ko.md#cmaa2--nis-업스케일링)을 확인하세요.

**화면 확대 방식**은 1:1이 아닐 때만 적용됩니다. 부드럽게는 기본 보간 방식이고,
선명하게는 드라이버가 지원할 경우 GPU Video Processor의 가장자리 보강을
사용합니다. 프레임 큐를 추가하지 않으며, 지원하지 않는 GPU에서는 부드럽게로
자동 대체됩니다.

**모니터 이동 시 상대적 창 크기 유지**는 해상도, DPI와 화면비가 다른 모니터
사이에서 영상 전체가 들어가는 축을 기준으로 비슷한 화면 점유율을 유지하고 다음
실행에도 복원합니다. 16:10 및 21:9/32:9 모니터에서도 영상 비율을 유지하며
불필요하게 한 번 더 축소하지 않습니다. Pixel-perfect와 독립된 옵션이므로 모니터
이동 후 1:1이 깨질 수 있습니다. 이때 `F5`를 누르면 정확한 크기로 다시 맞출 수
있습니다.

**제목 표시줄 숨기기**는 창 모드의 제목과 테두리를 제거합니다. 가장자리 스냅은
모니터 바깥 경계와 맞닿은 모니터 사이의 내부 경계에서 모두 작동합니다. 진입과
해제 거리는 DPI를 반영한 20 DIP이며, 드래그 중 Shift를 누르면 일시적으로
무시합니다.
