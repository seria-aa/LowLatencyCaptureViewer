# CMAA2 → NIS 경계·버퍼 안전성 수정

2026-10-26. 2.1.7 이후 작업이며 버전 발행/배포는 하지 않았다.

## 수정

- **NIS 가장자리 오염:** 음수 halo 좌표에 unsigned 값을 더하던 연산을 signed로 통일했다. viewport origin도 변환한다. 오른쪽/아래쪽 픽셀이 왼쪽/위쪽 계산에 섞이지 않는다.
- **NIS 출력 범위:** 끝 좌표는 포함하지 않도록 `>=`로 검사한다. 음수가 가능한 source 좌표는 unsigned 변환 없이 float로 비교한다. 사용하지 않는 sharpen 경로의 같은 경계 조건도 맞췄다.
- **CMAA2 용량 초과:** 후보·혼합 항목·위치 목록의 쓰기를 용량으로 제한한다. 저장하지 못할 혼합 항목을 연결 목록에 등록하지 않는다. 혼합 항목의 26비트 인덱스 한계도 검사한다.
- **안전한 출력:** 항목이 넘치면 GPU에서 해당 프레임의 AA 적용을 통째로 건너뛴다. 원래 SDR 영상에 NIS 확대는 계속 적용하고, 다음 정상 프레임에서는 CMAA2가 복귀한다. 무작위로 누락된 일부 AA만 표시하지 않는다.
- **방어 처리:** 잘못된 연결 인덱스 또는 기존 순회 한도를 넘는 연결 목록은 부분 혼합하지 않는다.

버퍼 크기·dispatch 횟수·캡처 큐는 그대로다. 매 프레임 CPU 읽기/대기를 추가하지 않았다.
일반 장면의 필터 방식·선명도·색 변환은 유지한다. 극단적으로 조밀한 입력에서 AA가 우회될 수 있다는 점은 의도된 안전 동작이다.
HDR에는 이 SDR 필터를 적용하지 않는다. 원본 스크린샷·녹화 경로와 OSD 표시 순서도 변경하지 않았다.

## 검증

새 `UpscalingSafetyTests`는 배포용으로 생성한 동일 셰이더를 실행한다. 참조 이미지끼리만 비교하지 않고 다음 조건을 직접 검사한다.

- 128/256 스레드 NIS 모두, FHD→QHD 및 1.25~2배/한 축 확대/홀수 크기에서 반대편 경계 변화가 현재 쪽에 영향을 주지 않음.
- 여백을 둔 텍스처와 이동한 출력 viewport에서 범위 밖 sentinel 보존.
- 실제 버퍼 용량을 넘는 97×73, 320×180, 1920×1080 합성 입력: AA 적용 dispatch 중단, 출력 반복 안정성, 원본 보존. 정상 프레임은 활성 위치 목록의 연결 인덱스를 검사한다.
- 후보·항목·위치 버퍼 각각을 작게 만든 강제 초과, 정확히 용량에 맞는 입력, 다음 프레임 복구.
- 하드웨어 GPU와 WARP에서 모두 통과. 다른 제조사 GPU 실물 검증을 뜻하지는 않는다.
- 최초 작성 당시의 테스트를 수정 전 라이브러리/셰이더로 빌드해 NIS 경계 검사와 CMAA2 초과 대응 검사가 각각 실패함을 확인했다. 이후 활성 목록·화면 전환 등을 보완한 현재 테스트 전체를 수정 전 셰이더로 재실행한 것은 아니다.

관련 **15개 테스트 모두 통과**:

`CmaaNisRegression`, `CmaaNisHdr`, `CmaaNisRecording`,
`UpscalingSafetyHardware`, `UpscalingSafetyWarp`, `VsrExperimentTests`,
`VideoClearRegression`, `SettingsControllerTests`, `CaptureFrameRateOsdTests`,
`MjpegRecordingPlaybackTests`, `HdrVsrPipelineTests`, `SettingsStoreTests`,
`SettingsStoreSaveFailureTests`, `SettingsStoreEmptyCacheTests`, `TestProfileTests`.

이는 합성 입력·GPU 출력·설정 격리 검사다. 새 HDMI 캡처나 육안 HDR 밝기 검사는 하지 않았다.
HDR/VSR 테스트는 출력 경로와 요청/우회를 검사하며 NVIDIA 드라이버의 VSR 향상 활성화를 증명하지 않는다.

## 처리 시간

RTX 3080, 합성 FHD→QHD, 기존 `CmaaNisTests --benchmark`로 수정 전/후 빌드를 교차 실행했다.
각 빌드에서 ON/OFF 각각 6라운드, 라운드마다 25프레임 준비 후 120프레임 측정.

| GPU 처리 시간 | 수정 전 평균 | 수정 후 평균 |
|---|---:|---:|
| 필터 끔 | 0.337 ms | 0.336 ms |
| CMAA2 → NIS 0.15 | 1.201 ms | 1.072 ms |

ON 라운드 평균 범위는 수정 전 0.910~1.478 ms, 수정 후 0.760~1.336 ms였다.
측정 변동이 있으므로 속도 향상을 확정하지 않는다. 이 범위에서 반복적인 성능 저하는 관찰되지 않았다.
이는 GPU 처리 시간이지 HDMI 입력부터 모니터 표시까지의 총지연이 아니다.

## 리뷰 후 테스트 보완

일반 빌드의 셰이더·버퍼·프레임 처리 코드는 추가로 바꾸지 않았다. 다음 보완은 테스트 실행 파일에만 들어간다. 후속 비동기 집계는 별도 진단 라이브러리/실행 파일에만 추가했다([진단 방법과 결과](UPSCALING_OVERFLOW_DIAGNOSTIC.md)).

- **활성 목록 검사:** 정상 프레임은 제어 word 3에 남은 위치 개수만큼만 head를 따라간다. 사용하지 않은 head는 초기화되지 않거나 이전 값이 남을 수 있으므로 검사하지 않는다. 활성 위치 범위·중복, 항목 범위·순환·quad 간 항목 공유를 검사하고, 검사기 자체에도 잘못된 목록을 주어 실패하는지 확인한다.
- **오버플로 검사 분리:** 이 경우 word 3은 0이고 append 카운터도 지워졌다. 따라서 연결 목록 전체가 유효하다고 주장하지 않고, 적용 개수 0·간접 dispatch 중단·원본 보존·복귀를 검사한다. 계측을 위해 제품 제어 버퍼에 값을 더 쓰지 않는다.
- **화면 전환:** head를 의도적으로 잘못된 값으로 채운 뒤 최초 평탄 화면, 정상 AA→평탄 화면, 오버플로→평탄 화면과 다음 정상 프레임을 검사한다. 비활성 head를 무시해도 활성 목록의 오류 검출은 유지된다.
- **연속 프레임:** 기존 57,600항목 버퍼로 320×180 노이즈 영역의 폭만 바꿔 경계를 찾는다. NIS 0.15로 480×270 확대하며 정상 8프레임·정상/초과 교대 8프레임·초과 8프레임을 실행한다. 영상 입력 자체가 바뀌지 않는 왼쪽 1/4 영역을 따로 비교한다.

### 합성 경계 장면의 관측 결과

| 측정 | RTX 3080 | WARP |
|---|---:|---:|
| 정상 / 초과 노이즈 폭 | 232 / 233열 | 232 / 233열 |
| 초과 프레임 / 전체 | 12 / 24 | 12 / 24 |
| 정상↔초과 전환 | 7회 | 7회 |
| 입력 불변 영역의 출력 최대 차이 | 0.478882 | 0.478882 |
| 같은 영역의 평균 차이 | 0.055096 | 0.055092 |
| 같은 영역에서 차이가 1/255를 넘는 픽셀 | 94.35% | 94.35% |
| 동일 정상 입력 반복 시 CMAA2 최대 차이 | 0.000488 | 0.000488 |
| 동일 정상 입력 반복 시 NIS 후 최대 차이 | 0.010254 | 0.041260 |
| 동일 정상 입력 반복 시 NIS 후 최대 평균 차이 | 0.00000027 | 0.00000153 |

차이는 0~1 RGB 값 기준이며, 합성 입력은 회색조라 평균·비율은 R 채널로 계산했다. 반복 비교는 각 상태의 첫 출력과 비교한다. 위 표는 첫 전체 회귀 실행의 관측값으로, GPU 병렬 처리에 따른 작은 반복 변동은 가능하다.

**전체 프레임 AA 생략에 따른 시간적 화질 변화가 합성 경계 장면에서 확인됐다.** 원본 입력이 동일한 영역도 정상/초과 상태에 따라 크게 달라진다. 12/24는 의도적으로 만든 스트레스 시퀀스의 비율이지 실제 게임·MJPEG의 발생 빈도가 아니다. 실제 게임의 깜빡임을 육안으로 확인했다는 뜻도 아니다. 안전성 테스트 통과가 이 화질 전환 문제까지 해결했다는 뜻은 아니다. 버퍼 증설이나 시간적 전환 완화는 아직 적용하지 않았다.

별도로, CMAA2의 FP16 혼합 순서에 따른 작은 반복 차이가 NIS의 비선형 판단을 거치며 일부 픽셀에서 증폭된다. 동일한 CMAA2 출력 이미지를 NIS에 다시 주면 차이는 0이었다. 최초 작성한 테스트의 근거 없는 NIS 후 최대 오차 기준(2/255)은 이 노이즈 입력에서 실패했다. 이를 단순히 완화하지 않고, CMAA2 반복 오차·동일 NIS 입력의 결정성 검사는 유지하며 NIS 증폭량은 관측값으로 분리했다. 평균 차이는 작지만 최대 차이만으로 무시하거나 실제 화면에서 보이지 않는다고 단정하지 않는다.

### 재실행 및 저장소 관리

15개 관련 테스트를 다시 실행했다. 첫 실행은 13개 통과, `SettingsStoreTests`와 `TestProfileTests`는 제한된 실행 환경에서 임시 INI 저장 권한 오류로 실패했다. 같은 두 바이너리를 정상 파일 권한에서 재실행하여 각각 25.62초·0.19초에 통과했다. 최종적으로 위 15개 모두 통과 결과를 확인했으며, 첫 실행의 실패 기록도 보존했다. 새 안전성 테스트는 하드웨어·WARP 각각 3회 연속 재실행도 통과했다. 이번에 성능 벤치마크는 다시 측정하지 않았고 위 처리 시간 표는 이전 수정 검증 결과다. 실제 설정 두 파일과 기존 v2.1.7 릴리스 실행 파일의 해시는 보완 전후 동일했다.

Windows/MSVC 테스트 빌드에서 다음 명령으로 새 검사를 재현할 수 있다. GPU 합성 입력만 사용하며 실제 캡처 장치나 앱 설정은 필요하지 않다.

```text
cmake --build build-upscaling-safety --target UpscalingSafetyTests
ctest --test-dir build-upscaling-safety -R "^UpscalingSafety(Hardware|Warp)$" -V
```

새 체크아웃은 기존 빌드 안내에 따라 `BUILD_TESTING=ON`인 Release 빌드를 먼저 구성한다. `SEQUENCE`와 `REPEAT` 행으로 경계 전환과 반복 오차를 각각 확인할 수 있다. 테스트 안에서만 GPU 값을 읽으며, 이 읽기 대기는 앱 성능 측정에 포함시키면 안 된다.

`/outputs/` 전체를 커밋 제외 대상으로 지정했다. 기존 자료는 삭제하지 않았으며, 제외되지 않은 untracked 파일 수가 0임을 확인했다. 결과 요약과 재현 가능한 테스트 소스는 `docs/`와 `tests/`에 남긴다. `outputs/`의 원시 로그는 로컬 보조 자료이며 저장소에 포함되지 않는다.

로컬 원시 자료: `outputs/upscaling-safety-fix/`의 전후 timings.csv, `core-tests.log`, `related-tests.log`, `review-regression.log`, `review-profile-tests.log`, `review-safety-repeat.log`. 이전 추가 실행은 `outputs/nis-boundary-audit/final-safety-tests.log`, `hdr-vsr-verbose.log`에 있다.
