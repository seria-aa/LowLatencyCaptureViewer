# 실시간 정보창과 로그

[README](../README.ko.md) · [문서 목록](INDEX.ko.md) · [English](DIAGNOSTICS.md)

[영상 항목](#영상-항목) · [오디오 항목](#오디오-항목) · [버퍼 용어](#버퍼-용어) · [버퍼 진단 방법](#버퍼-진단-방법) · [로그 파일](#로그-파일)

뷰어에서 `Tab`을 누르면 실시간 정보창을 표시하거나 숨길 수 있습니다.

이 문서의 키는 기본값입니다. [단축키를 변경했다면](USAGE.ko.md#단축키-변경)
해당 기능에 지정한 키를 사용하세요.

영상 모드에서는 `F3`으로 오디오 미터 OSD를 표시하거나 숨길 수 있습니다.
오디오 전용 모드는 별도의 상시 표시 화면에서 마스터 음량, L/R 피크·채널 음량,
클리핑 상태를 보여줍니다. L/R 카드 위의 휠로 개별 음량을 조절할 수 있습니다.
오디오 전용 화면에서는 마스터·L/R 영역을 두 번 클릭하면 해당 음량이 100%로 복원됩니다.
영상 OSD의 두 번 클릭은 창 형태에 따라 창 이동 동작에 가로막힐 수 있으므로,
오디오 전용 화면과 동일하게 동작한다고 가정하지 마세요.

<br>

## 영상 항목

- **경로:** 선택한 캡처 장치와 DirectShow→D3D11 경로
- **입력:** 실제 해상도, FPS와 픽셀 포맷
- **영상 품질:** 색 범위와 D3D11 처리 경로
- **표시:** 출력 크기, 확대 방식, 스왑체인과 표시 모드
- **실제 FPS:** 측정한 입력·Present 속도
- **앱 처리 지연:** 앱 내부에서 걸린 시간이며 HDMI 전체 지연은 아님
- **프레임:** 입력, 출력, 최신화 교체 또는 버린 횟수

이전 프레임을 표시하기 전에 새 샘플이 들어오면 최신화 교체가 발생할 수 있습니다.
숫자가 증가한다고 앱이 지연을 쌓는다는 뜻은 아닙니다. 오히려 대기열을 막기 위해
오래된 샘플을 버리는 동작입니다.

영상 통계는 시작 후 첫 5초를 집계에서 제외합니다.

40fps 캡처를 켠 경우에도 형식에 적힌 FPS만 보지 말고 **실제 FPS**의 입력 속도를
확인하세요. 이는 앱에 도착한 샘플 수이며 게임의 고유 프레임 수나 콘솔의 HDMI
출력 Hz를 뜻하지 않습니다. 같은 화면을 반복한 샘플도 입력 FPS에 포함됩니다.
LS가 이후 생성한 프레임은 LLCV의 Present FPS에 포함되지 않습니다.
직접 선택한 FPS보다 실제 입력이 지속적으로 높으면 같은 줄과 로그에 경고합니다.
이 경고는 드라이버의 전달 속도를 알리는 것이며 소프트웨어 프레임 제한을 추가하지 않습니다.

<br>

## 오디오 항목

- **오디오 출력:** 실제 WASAPI/ASIO 모드와 장치, 출력 버퍼와 WASAPI 현재 점유량
- **캡처 오디오:** 입력 패킷 크기와 콜백 간격
- **클록 보정:** 사용 여부와 적용 중인 속도 보정량
- **PCM 버퍼:** 현재, 목표와 관측한 최소 대기량
- **오디오 오류:** underrun/overrun 횟수와 지속 시간
- **오류 원인·추세:** 최근 진단과 장시간 불균형 추정값

ASIO 시작에 실패해 WASAPI Shared로 대체되면 정보창에는 Shared와 실제 출력
장치를 표시합니다. 저장한 ASIO 선택은 다음 시도를 위해 유지되므로, 대체 후
실제로 사용 중인 출력 모드와 다를 수 있습니다.

오디오 오류 진단은 시작 후 첫 5초를 집계에서 제외합니다. 캡처와 재생을 5초 뒤에
시작하는 것이 아니라 통계만 워밍업을 기다립니다.

ppm은 하드웨어 클록을 직접 측정한 값이 아니라 동작상 추정값입니다. 시작 구간과
스케줄링 지연에도 영향을 받으므로 ppm만 보고 보정을 켜기 전에 안정된 상태로
10~30분 관찰하세요.

<br>

## 버퍼 용어

- **출력 버퍼:** WASAPI 출력 장치 버퍼 또는 ASIO 드라이버 버퍼
- **출력 점유:** WASAPI 출력 장치 버퍼에 현재 들어 있는 오디오
- **PCM 버퍼:** 캡처와 재생 사이의 앱 내부 안전 대기열

서로 다른 값입니다. PCM 목표를 올리면 앱의 오디오 대기량이 늘고, WASAPI 요청을
바꾸면 출력 장치 쪽 period 또는 버퍼에 영향을 줍니다.

가끔 한 번 발생한 underrun은 반드시 들리는 문제이거나 치명적인 오류라는 뜻은
아닙니다. 반복된다면 먼저 출력 장치가 안정적인지 확인하고 PCM 목표를 한 단계
올리세요. 클록 보정은 일시적인 스케줄링 중단이 아니라 한 방향으로 계속 커지는
드리프트가 관측될 때 사용합니다.

<br>

## 버퍼 진단 방법

Tab 진단창에서는 다음 순서로 확인하면 됩니다.

- **현재 PCM 버퍼:** OSD를 갱신한 순간의 앱 내부 대기량입니다. 렌더 콜백 직후에는
  일시적으로 낮게 보일 수 있습니다.
- **목표:** 앱이 유지하려는 PCM 대기량입니다.
- **관측 최저:** 렌더 콜백 경계에서 관측된 세션 중 최저 대기량입니다. 현재 값과
  측정 시점이 다르므로 현재 값보다 높거나 낮을 수 있습니다.
- **underrun:** 실제로 출력할 PCM이 부족했던 횟수입니다.

판단 기준은 다음과 같습니다.

1. **underrun 0회 + 버퍼 진단 정상:** 현재 설정을 유지합니다.
2. **`버퍼 부족` 또는 `리샘플러 출력 부족`이 반복:** PCM 목표를 `10 → 15 → 20 → 25 → 30 ms`
   순서로 한 단계씩 올립니다. 둘 다 앱의 PCM 안전 여유가 부족할 때 나타날 수
   있으므로, 먼저 PCM 목표를 조정하는 것이 맞습니다.
3. **`입력 지연`만 반복:** 캡처 콜백 지연이나 시스템 스케줄링 문제를 의심합니다.
   PCM 목표를 올려도 해결되지 않을 수 있습니다.
4. 한 번 발생한 오류보다 **최근 오류 패턴과 최대 연속 횟수**를 우선 봅니다. 가끔
   한 번 발생하고 이후 정상이라면 체감되지 않을 수 있지만, 짧은 간격으로 반복되거나
   연속 횟수가 늘면 버퍼를 조정해야 합니다.

ASIO에서는 **앱 PCM 버퍼와 ASIO 드라이버 출력 버퍼가 별개**입니다. 앱 PCM 진단이
정상인데도 ASIO에서 끊김이 반복되면 ASIO 드라이버 설정의 출력 버퍼도 확인하세요.

새 설치의 PCM 목표는 **25ms**입니다. 이전 버전에서 저장한 20ms는 처음 실행할 때
한 번만 25ms로 옮기며, 다른 저장값은 유지합니다. 이후 직접 20ms를 선택할 수 있습니다.
안정적인 동작을 확인한 뒤 지연을 더 줄이려면 `25 → 20 → 15 → 10ms` 순서로
낮추세요. 오류가 반복되면 한 단계씩 올리고, 25ms에서도 부족하면 30ms를 시험하세요.

<br>

## 로그 파일

**도움말·진단** 탭에서 **진단 로그 파일 저장**을 켜면 다음 위치에 기록됩니다.

```text
%LOCALAPPDATA%\LowLatencyCaptureViewer\logs
```

선택한 장치와 모드, 실제 allocator 크기, WASAPI 초기화와 대체 경로, 캡처 그래프
진행 단계가 기록됩니다. 초기화에 실패하면 필터의 핀과 미디어 타입 정보도 함께
남깁니다.

오디오 처리 중의 진단은 대기열이나 카운터에 모아 두고 오디오 콜백·처리 경로
밖의 UI 스레드에서 나중에 출력합니다. 오디오 오류 이력은 크기가 제한된 저장
공간을 사용해 메모리 할당을 줄입니다. UI가 바빠 진단 대기열이 가득 차면 메시지를
생략할 수 있으며 생략한 수를 로그에 남깁니다. 이 변경이 측정된 지연이나 FPS
개선 수치를 뜻하지는 않습니다.

표시 문제가 발생하면 `display-event`의 디스플레이·장치 변경 시각과 swapchain
가림/복귀 기록을 확인하세요. D3D11 전송·Present·출력 재생성 실패가 발생하면
HRESULT와 `GetDeviceRemovedReason` 결과가 `video-event`로 함께 기록됩니다. 정상
프레임마다 이 이벤트 로그를 남기지는 않습니다.

저장 로그는 자동으로 제한됩니다. 파일 한 개는 최대 2 MB이며, 최신 관리 대상 로그
최대 5개와 총 10 MB까지만 유지합니다. 7일이 지난 관리 대상 로그는 새 로그 세션을
시작할 때 정리됩니다. 오래 실행하면 `..._part02.log`처럼 나뉠 수 있으니 문제를
제보할 때는 같은 세션의 모든 part 파일을 함께 첨부해 주세요.

**진단 콘솔 창 표시**는 같은 진단 출력을 콘솔에서 실시간으로 보여줍니다. 기본은
꺼짐이며, 콘솔을 켜지 않아도 파일 로그 저장에는 지장이 없습니다.

문제를 제보할 때는 전체 로그와 함께 캡처보드 모델, 입력 해상도/FPS, 선택한 픽셀
포맷, 캡처 오디오 장치와 출력 장치를 알려주세요.
